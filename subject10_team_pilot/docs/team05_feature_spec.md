# 팀05 Feature 명세 (4일차 산출물 ⑥)

> 프로젝트: 맨몸운동 정석 자세 판정 (버피·스쿼트 점프·런지)
> 판정 방식: 정석 규칙(GLB 근거 숫자)에서 벗어나면 NG, 관측이 불가능하면 CHECK
> 코드: `src/feature_utils.py`(교과 3일차 원본), `src/team_feature_utils.py`(팀 확장)

## 1. Frame Feature 구성

| 구분 | 열 | 개수 | 출처 | 비고 |
|---|---|---:|---|---|
| 교과 38-D | `<관절>_x`, `<관절>_y` (COCO 17) | 34 | 3일차 정규화 | 열 이름·순서 수업과 동일 |
| 교과 38-D | `left/right_elbow_angle`, `left/right_knee_angle` | 4 | 3일차 `calculate_angle` | 0~180° |
| 팀 추가 | `left/right_hip_angle` (어깨–엉덩이–무릎) | 2 | 팀 | 런지·스쿼트 깊이 |
| 팀 추가 | `left/right_leg_ratio`, `leg_ratio` | 3 | 팀 | 다리 높이 / 몸통 길이 → 반복 구간 분할·깊이 |
| 팀 추가 | `left/right_body_line_offset` | 2 | 팀 | 어깨–발목 선에서 엉덩이가 벗어난 정도 (버피 플랭크) |
| 품질 | `<관절>_conf` (17), `mean_keypoint_conf`, `low_keypoint_count`, `valid_pose` | 20 | YOLO | 학습 입력 아님, 판정 신뢰도 확인용 |
| 정규화 기준 | `norm_scale_mode`, `norm_scale_px` | 2 | 팀 | shoulder / torso |
| 출처 | `clip_id`, `subject_id`, `action_label`, `view`, `source_type`, `frame_id`, `time_sec` | 7 | Manifest | |

**판정에 쓰는 Feature = 38-D + 팀 추가 7개 = 45개.**
교재의 5팀 제안(+5 → 43-D: 고관절 2, 어깨 각도 2, 상체 기울기 1)과 비교하면 다음과 같다.

| 교재 제안 | 우리 구현 | 이유 |
|---|---|---|
| 고관절 각도 2 | 그대로 사용 | 런지 앞다리 고관절, 스쿼트 깊이 |
| 상체 기울기 1 | `body_line_offset` 2개로 대체 | 버피는 상체 각도보다 **허리 처짐·엉덩이 들림**이 핵심 |
| 어깨 각도 2 | 사용 안 함 | 세 동작의 정석 규칙에 어깨 각도 조건이 없음 |
| (없음) | `leg_ratio` 3개 추가 | 1회 구간 자르기와 스쿼트 점프 깊이 판정에 필요 |

원본 Pixel 좌표는 `reports/team_projects/team05/keypoints/<clip_id>_keypoints.csv`에 따로 보존한다.

## 2. 정규화

| 각도 | 방식 | 이유 |
|---|---|---|
| 정면·사선 | 골반 중심 이동 + **어깨 폭**으로 나눔 (교과 방식) | 수업과 동일 |
| 측면 | 골반 중심 이동 + **몸통 길이**(어깨중점–엉덩이중점, 90백분위)로 나눔 | 측면에서는 어깨 폭이 0에 가까워져 값이 폭주함 (4일차 `walk_turn_walk` 변화량 17.18과 같은 원인) |

`choose_scale_mode`가 영상마다 자동 선택한다(예: EXT_S09 사선은 몸이 많이 돌아가 torso 선택).

## 3. 1회(rep) 단위 측정값

| 측정값 | 계산 | 쓰는 동작·각도 |
|---|---|---|
| `depth` | 1회 중 최저 `leg_ratio` / 서 있을 때 `leg_ratio` | 스쿼트 점프 (정면·사선·측면) |
| `knee_spread_bottom` | 최저 구간의 두 무릎 간격 / 두 발목 간격 | 스쿼트 점프 정면 (무릎 모임) |
| `knee_min`, `hip_min` | 1회 중 최소 각도 | 런지 측면·사선, 스쿼트 점프 참고 |
| `body_line_min/max` | 플랭크 Frame(몸통·다리가 수평에 가까움)에서만 | 버피 측면·사선 |
| `curve_dist` | 무릎·고관절 곡선(48점)과 GLB 정석 곡선의 평균 차이 | 버피 |
| `low_conf_ratio` | 1회 중 무릎·고관절 측정 불가 Frame 비율 | 전 동작 (CHECK 판단) |

## 4. 정석 규칙 (configs/team_project.json `rules`)

| 동작 | 판정 각도 | 규칙 | 근거 |
|---|---|---|---|
| 스쿼트 점프 A008 | 정면·사선·측면 | `depth ≤ 0.55` | GLB depth 0.258 |
| | 정면 | `knee_spread_bottom ≥ 0.80` | GLB 1.28 |
| 버피 A001 | 측면·사선 | 허리 처짐 `body_line ≥ −0.15`, 엉덩이 들림 `≤ 0.55`, 동작 흐름 `curve_dist ≤ 30°` | GLB body_line 측면 −0.08~0.38 |
| 런지 A004 | 측면 | 앞무릎 `60~115°`, 앞다리 고관절 `≥ 60°` | GLB 없음 → 팀 정의 |
| | 사선 | 팀 정석 영상 분포 (임시) | 원근 때문에 절대 각도 규칙 미적용 |

정면 버피·정면 런지는 판정하지 않는다(CHECK). 정면에서는 허리 처짐과 무릎 각도를 측정할 수 없기 때문이다.

## 5. 다리 선택 (`leg_combine`)

| 값 | 동작 | 방식 |
|---|---|---|
| `mean` | 버피·스쿼트 점프 | 측면은 카메라 쪽 다리, 정면·사선은 좌우 평균 |
| `front` | 런지 | **측면:** 진행 방향으로 발목이 더 나간 다리를 앞다리로 선택. 다리 길이 검사(정강이·허벅지가 서 있을 때 길이의 ±35%)를 통과한 Frame만 사용. 발목이 반대 다리로 잡힌 Frame은 교환 보정 / **사선:** 좌우 중 작은 각도(`min`) |

`front` 도입 이유: EXT_S07 런지 측면에서 YOLO가 앞다리 무릎을 발목 근처에 찍었다(정강이 길이가 기준의 10~30%). Confidence는 0.95 이상이었다. 기존 `min` 방식은 이 값을 그대로 써서 정석 런지 2회를 NG로 오판정했다. 수정 후 해당 회차는 **CHECK**(측정 불가)로 바뀌었다.

## 6. 결측·신뢰도 처리

- 관절 Confidence < 0.50 → 그 관절이 들어간 각도는 NaN (NG가 아님)
- 1회 중 측정 불가 비율이 높으면 → **CHECK**
- VICON(GLB) 관절에는 Confidence가 없으므로 **NaN으로 둔다**(1.0으로 채우지 않음). 얼굴 관절은 VICON에 없어 NaN이다.
